# Архитектура DENTARA

Сайт остаётся статическим и размещается на существующем GitHub Pages. HTML содержит основное англоязычное содержимое; небольшие ES-модули добавляют взаимодействия.

```text
index.html + styles.css + editorial.css
                   ↓
               script.js
                   ├─ controls.js → галерея / theme / навигация / range / FAQ
                   ├─ motion.js   → reveal / параллакс / reduced motion
                   └─ booking.js  → validation.js → локальное превью
                           ↑
                       layers.js → native dialog
```

`dom.js` создаёт элементы, SVG-иконки и безопасно читает/пишет необязательные предпочтения. `content.js` содержит авторские данные интерфейса. Единственный монолитный script заменён модулями с отдельной ответственностью; HTTP-сервисы для браузерных вкладок не требуются.

## Диалоги

`showModal()` использует нативную изоляцию фона и удержание фокуса. Контроллер держит один активный слой. Переход «направление → запрос» закрывает исходный слой и переносит адрес возврата фокуса. Каждое открытие/закрытие меняет номер версии и отменяет старый таймер и animation frame: задержка прежнего закрытия не может скрыть повторно открытый диалог.

При закрытии восстанавливается фокус без прокрутки. Страница блокирует scroll через overflow; фиксирование body и принудительное изменение scrollY не применяются. Мобильное меню также нативный dialog, имеет собственную кнопку закрытия и закрывается при переходе в desktop-layout.

## Форма и данные

Весь сценарий локальный. Сетевой функции доставки заявок в этом репозитории нет. Поля проверяются при submit, включая autofill; сообщения привязаны к полям через `aria-describedby`/`aria-invalid`. Переход назад сохраняет данные в объекте в памяти. Закрытие удаляет объект и DOM полей.

Значения формы никогда не попадают в `innerHTML`, HTML-атрибуты или строковые шаблоны разметки. Поля восстанавливаются через `.value`, итоговое превью создаётся с `textContent`. Форма явно сообщает, что ничего не отправлено и не забронировано; серверные обещания удалены.

## Медиа и движения

Основная фотография — `img` с заданной геометрией и высоким приоритетом. Остальные новые изображения используют WebP. В галерее `Image.decode()` загружает новую картинку до замены, а номер текущего запроса не допускает гонок при быстрых переключениях.

Сравнение использует обычный `input[type=range]`: нативное управление указателем, touch и клавиатурой, без второй системы pointer-событий и дополнительного click-сдвига. Видимые слои и подпись `aria-valuetext` синхронизируются из `input`.

Reveal отслеживается через IntersectionObserver, параллакс ограничен одним requestAnimationFrame на событие прокрутки и видимостью изображения. Режим reduced motion отслеживается динамически и имеет приоритет над сохранённым пользовательским выбором. CSS-анимации приостанавливаются в скрытой вкладке. При отсутствии JS основное содержимое остаётся видимым; класс для reveal добавляется только после инициализации.

## Границы

Нет базы пациентов, авторизации, API записи, оплаты или секретов. Для перехода к реальной клинике потребуется отдельная задача на сервер приёма обращений, правила доступа/обработки данных, инфраструктуру и проверенные сведения клиники. Это не повод добавлять несколько микросервисов к текущему статическому концепту.

Визуальные ориентиры: редакционная подача и спокойная иерархия [Mouth Dental](https://mouth.co.uk/) и внимание к пространству/комфорту [Tend](https://www.hellotend.com/site/culture). Чужие фотографии и тексты не переносились; использованы ресурсы исходного репозитория и собственные SVG/CSS-акценты.
